# 2026-11-04-001: Kickoff, "a Run & Debug for Flutter in Zed"

## What the user asked
They want a Run & Debug experience for Flutter in Zed that matches VS Code's (reference: microsoft/vscode, i.e. the Run & Debug view plus the Dart-Code extension). They also want every milestone and every useful conversation documented in `/docs`, so the docs can guide the build.

## Background they brought (from another AI chat)
- "Zed has a built-in DAP debugger for C/C++/Go/JS/TS/Python/Rust/PHP, and it falls back to `.vscode/launch.json`." **Correct.**
- "Flutter isn't supported because it doesn't use a standard debugger, so it'd need DAP plus hot reload, DevTools and device daemons." **Partly wrong.** Flutter does ship a standard DAP server (`flutter debug-adapter`), and the official Zed Dart extension already wires it up. What's actually missing is the Flutter-specific UX on top: hot reload/restart, a device picker, and DevTools.

## What we found
See [research/landscape.md](../research/landscape.md). In short:
- Basic debugging already works today (the Dart ext v0.4.1 is installed locally).
- The biggest gap is hot reload/restart. ~~The upstream fix is waiting on a new Zed API (zed#51873).~~ **Correction:** zed#51873 was closed unmerged on 2026-08-19.
- The device picker and DevTools launch have no solution yet.

## Proposed direction (not decided yet)
Don't rebuild the debugger. Build the missing layer:
1. **Companion tool first.** A small CLI/daemon that lists devices, writes `.zed/debug.json` entries, and triggers hot reload (`flutter run --machine` / DAP custom request), wired into Zed **tasks** and keybindings. It works with today's Zed API.
2. ~~Contribute upstream once zed#51873 lands~~. **Correction:** that PR was closed unmerged (see 002).
